Run `zsh notchcast/settings-snapshot.sh <Debug.app> <output> [comma-separated-slugs]` to use the gallery's isolated launch and WindowServer monitor for Settings only. The default slug is `notchcast`; include reference tabs explicitly, for example `notchcast,general,clipboard,about`. No normal app startup runs.

The output contains `<slug>-{light,dark}.png`, their gallery layout exports, and `timings.json`. Each appearance has five raw open and switch samples in milliseconds plus their medians. Open starts immediately before creating the 800 × 800 detail host with the real Settings environment. Switch starts at `navigation.select(tab)` on that same live host after rendering General (About when the destination is General). Each interval yields to pending main-actor updates, performs layout, and draws through `cacheDisplay`; PNG encoding and disk writes are excluded. This measures offscreen detail rendering, not window chrome, compositor latency, complete asynchronous data loading, or cold process startup. The shared core and caches persist across trials; the first raw open sample includes lazy initialization.

Set `NOTCHCAST_GALLERY_SETTINGS=1` and optionally `NOTCHCAST_SETTINGS_TABS` when invoking the isolated gallery launcher directly. The Settings-only runner uses the existing gallery window factory and capture code. It does not change Settings pages or start feature modules.
