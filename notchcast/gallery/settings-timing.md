Run `zsh notchcast/settings-snapshot.sh <Debug.app> <output> [comma-separated-slugs]` to use the gallery's isolated launch and WindowServer monitor for Settings only. The default slug is `notchcast`; include reference tabs explicitly, for example `notchcast,general,clipboard,about`. No normal app startup runs.

For real on-screen timing, run `NOTCHCAST_SETTINGS_TRIALS=5 zsh notchcast/settings-onscreen-timing.sh /absolute/path/Notchcast\ Dev.app /absolute/path/empty-output notchcast,general,clipboard,about` in an unlocked graphical login session. The bundle must have identifier `app.notchcast.dev`. This intentionally shows and activates Settings; it skips the offscreen monitor. The disposable home, sandbox and network denial still apply. Normal startup, modules, island and hotkeys do not run. Motion is disabled, as in the offscreen gallery.

On-screen open starts before `SettingsCoordinator.showSettings(tab:)`, with Settings closed. It includes creation of the real Settings root, sidebar, toolbar, window chrome and window activation. Switch starts before that same coordinator selects the destination in an already open window, after General (About for General) has reached the same frame boundary. Each trial closes the window; success and failure also close it before process exit. Light and Dark each receive the requested number of trials (default five).

The end signal yields to pending UI work, lays out the outer content view, calls `window.displayIfNeeded()`, flushes `CATransaction`, then waits for the first callback from that window's `CADisplayLink`. The link is registered only after the flush, so the callback marks the next refresh opportunity following submission to WindowServer. This measures submission plus refresh alignment, not proof of physical scanout or GPU completion. A missing callback fails after five seconds. Process startup, source-tab preparation, PNG encoding, disk output and complete asynchronous data loading are excluded; core and caches persist across trials. Do not compare these values directly to CPU bitmap-shadow rendering in offscreen samples.

`timings.json` retains the array of Measurement objects and adds `onscreen: true` and `screenRefreshRate` (Hz from the display link's target interval, sampled on the final open per appearance). Variable-refresh displays may change cadence during a run. Standard error contains trial progress. `loadavg-before.txt` and `loadavg-after.txt` record `sysctl -n vm.loadavg`; no screenshots are written.

The output contains `<slug>-{light,dark}.png`, their gallery layout exports, and `timings.json`. Each appearance has `NOTCHCAST_SETTINGS_TRIALS` (default five) raw open and switch samples in milliseconds plus their medians. Open starts immediately before creating the 800 × 800 detail host with the real Settings environment. Switch starts at `navigation.select(tab)` on that same live host after rendering General (About when the destination is General). Each interval yields to pending main-actor updates, performs layout, and draws through `cacheDisplay`; PNG encoding and disk writes are excluded. This measures offscreen detail rendering, not window chrome, compositor latency, complete asynchronous data loading, or cold process startup. The shared core and caches persist across trials; the first raw open sample includes lazy initialization.

Progress lines go to standard error after each trial. Set `NOTCHCAST_GALLERY_SETTINGS=1` and optionally `NOTCHCAST_SETTINGS_TABS` when invoking the isolated gallery launcher directly. The Settings-only runner uses the existing gallery window factory and capture code. It does not change Settings pages or start feature modules.

After timing, the final host settles and expands to its scroll document height at 800 pt wide before capture. The PNGs use the gallery's 2× scale. `manifest.txt` supports `swift notchcast/gallery/check-pixels.swift <output>`; sizing and PNG encoding are outside the timed intervals. Display uses the outer AppKit capture view, matching the repaired gallery renderer. Set `NOTCHCAST_SETTINGS_ALL_ON=1` to turn every wired feature on in the isolated home first, so pictures show each switch's commands and settings.
