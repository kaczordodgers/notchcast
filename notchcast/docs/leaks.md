# Leak points: the maintainer's employer must never appear

Notchcast is public. Nothing in it may name or point at the maintainer's employer: not its name, domain, email addresses, bundle id prefixes, internal repositories or paths. Where a leak can come from, and what stops it:

- **Commit identities.** A Mac's global git identity can be a work address, and every commit made the default way carries it. Each clone sets a repo-local identity before the first commit (`user.name`, a GitHub noreply `user.email`); workflow commits use `github-actions[bot]`.
- **Commit messages and labels.** Messages, LaunchAgent labels, bundle ids and signing identities are as public as code. Labels are `notchcast.<name>`, the bundle id is `app.notchcast`.
- **Unpushed and dangling objects.** A local commit with a bad message stays in the clone's object store and reflog, and tools that keep their own refs can keep it reachable. Never push a branch that contains one; rebuild the branch from `origin` instead.
- **Copied files.** Scripts, templates, design tokens or notes copied from private repositories bring absolute paths, internal names and ids with them. Review every copied file for paths and names before committing it.
- **Pushing to upstream.** Each clone sets `git remote set-url --push upstream DISABLED`.

Enforcement: `notchcast/check-identity.sh` runs in pre-commit, commit-msg, pre-push and CI (`git config core.hooksPath notchcast/githooks`). `history [base] [head]` checks only added lines in the endpoint diff plus full messages and author/committer metadata in that range; the default base is `refs/remotes/upstream/main`. It also checks each commit's added lines, so text added and removed again within one push still fails, but only in commits not yet on the fork's main (`git log --cherry-pick --right-only origin/main...HEAD`; in PR CI, `origin/$GITHUB_BASE_REF`): already-public history cannot be rewritten, and copies rebased by sync match by patch. `diff` and `metadata` run those checks separately. Staged mode checks added index lines and the next commit's identities. The guard rejects employer names and private task/thread identifiers, reporting locations and redacted categories only. Exact-path scanner-source exceptions are listed with reasons in the Python helper and reported when used. Pre-push checks each pushed head against its upstream merge base, with gitleaks over the same range. CI also checks strings from every file in the built app through `app <bundle>`. The email checker permits only eight exact historical author commits; all new identities remain checked. Gitleaks covers secrets independently.
