# Screenshots and the Capture Editor

The Screenshots add-on (`Tinycast/Features/Notchcast/Screenshots/`, switch `screenshot`, Settings › Notchcast › Capture) captures an area, a window or a display, and its Capture Editor annotates a capture before it is copied or saved. Both share one module, `ScreenshotsModule`, and one seam to the Mac, `ScreenshotSystem`. The editor is an adaptation of Vorssaint's screenshot editor (GPL-3.0-or-later), cut to the tools below; each derived file carries its notice and a line in `notchcast/licenses/borrowed/Screenshots.txt`.

## Invariants

- **One thing at a time.** A capture session or an open editor makes the module busy; Capture Area, Capture Screen and Edit Last Screenshot are ignored until it ends. So the capture an editor holds is never replaced under it.
- **The original is never written over.** The editor draws marks over the capture and renders a new image on Copy or Save; Save always writes a new file. A crop replaces the image inside the editor only, as an undo step. The last capture is kept as PNG data with its scale (`lastCapture`), not a bitmap, so Edit Last Screenshot opens the uncropped original again and costs no full-size image between edits. It lives in memory only and goes when the switch goes off or the app quits.
- **What is seen is what is copied.** The canvas and the exported result draw through the same `AnnotationRenderer.draw`, in image pixels with the origin top left; the editor shows it scaled to fit.
- **A blur area never shows what is under it.** It paints from a small sample of the whole capture (`AnnotationBlurSources`), shaken by seeded noise, and replaces the pixels instead of blending; a mark changes blur style only once the new sample exists, and an area with no sample is filled black.
- **The module closes the editor, never the editor itself.** The editor answers `CaptureEditorOutcome` (`.copy`, `.save`, `.saveAs`, `.close`, `.discard`); the module writes the result and only then closes it, so a failed write reports through an island failure notice and leaves the editor open with every mark. Switching Screenshots off closes it and drops the last capture.
- **A close never loses work silently.** `.close` (`⌘W`, `Escape` with nothing selected) closes at once only when `AnnotationDocument.isDirty` is false; otherwise it asks "Discard this screenshot's edits?" through `context.confirmDestructive` and Cancel keeps the editor open. Unsaved means the output differs from the capture as it opened or from what was last copied, saved or dragged out (`markExported`), text still being typed included; undoing back to that state is clean again. Only `.discard` (`⌘⌫`, the Discard button) drops work without asking.
- **The model has no UI.** `Model/Annotation*.swift` (tools, marks, geometry, drags, undo history, key map, renderer) imports Foundation, Core Graphics, Core Text, Core Image, ImageIO and UniformTypeIdentifiers only, and takes the pixels-per-point scale and the noise seed as parameters.
- **The scale is the capture's, not the screen's.** Pixels per point are read at capture from the frozen display the picture came from (for a window, the display holding its centre), kept with the last capture and handed to the editor, so marks and the window size match the capture wherever the pointer is when the editor opens. Every PNG, the plain capture and the editor's export alike, carries it as its DPI (144 for a Retina capture), so both open and paste at the same size in points.

## Using it

- **Edit after capture** (Screenshots option, off by default): every new capture opens in the editor instead of going to the screenshot destination. With it on, the Screenshot folder can be chosen under any destination, since Save writes there.
- **Edit Last Screenshot** (launcher command, `command:nc-edit-last-screenshot`, symbol `pencil.tip.crop.circle`, owned by the `screenshot` switch): opens the last capture; with none yet it posts "No screenshot to edit yet.".
- **Tools**, in rail order, each with a number key: Select `1`, Arrow `2`, Blur `3`, Crop `4`, Text `5`, Rectangle `6`, Highlighter `7`, Ellipse `8`. The editor opens on Arrow.
- **Style**, in the bar under the capture, for the picked tool or the selected mark: eight colours; three stroke widths (2, 4 and 7 points) for arrow, rectangle and ellipse; twelve text sizes (10 to 96 points) stepped by Smaller Text and Larger Text; Pixelate or Soft Blur for a blur area. Picking a style restyles the selected mark too, as an undo step.
- **Editing a mark.** The mark just drawn stays selected: a drag on it moves it, its eight handles (an arrow's two ends) reshape it, Delete removes it. Under a drawing tool a tap on a mark's edge selects it and switches to Select; the inside of a box stays free for new marks. A tap on a text edits it. Escape lets go of the selection. A click that draws nothing leaves no undo step and keeps the redo history.
- **Crop** starts on the whole image: drag a new frame, move it, or resize it by its handles, then Apply Crop (`Return`) or Cancel (`Escape`). Applying cuts the image and shifts every mark with it.
- **Undo `⌘Z` and Redo `⇧⌘Z`** cover every tool, moves, resizes, restyles, deletes and the crop; one drag is one step, and the newest 60 steps are kept.
- **Ways out:** Copy (`⌘C`, or `Return` outside a crop) puts the PNG on the clipboard and the island says "Copied"; Save `⌘S` writes it to the screenshot folder (Downloads when none is chosen) under the usual `Screenshot <date> at <time>.png` name; Save As `⇧⌘S` opens the system save panel on that name; both say "Saved to <folder>". The Drag chip drags it into another app as a PNG file (written to a temporary folder of this editor, removed when it closes). Close (`⌘W`, or `Escape` with nothing selected) asks first when there is unsaved work; Discard (`⌘⌫` or the button) closes without asking or writing. Copy and Save close the editor once the write succeeds. A held `Return` or `⌘C` acts once, and a `⌘C` another process posts within 0.6 s of a press or drag in the editor (a select-to-copy utility) is ignored. While text is typed, Escape finishes the text, `⌘S`, `⇧⌘S` and `⌘W` still work, and every other key belongs to the text field.

## Scrolling Capture

**Scrolling Capture** (launcher command, `command:nc-scrolling-capture`, symbol `arrow.up.and.down.square`, owned by the `screenshot` switch) joins a long page into one tall image. It is a port of Vorssaint's scrolling capture (faada18d), without its auto-scroll: the user scrolls.

### Invariants

- **Every join is checked.** `ScrollStitchMatcher` finds how many rows two successive frames share on greyscale samples up to 256 columns wide. An equally good rival offset or unexplained movement can leave the frame unmatched. It checks nearby offsets in colour on the sampled moving columns and uses the greyscale offset if all clean colour candidates have zero mismatches and include that offset. Scrolling back keeps the furthest frame and leaves any unresolved mismatch pending. If Finish still has a mismatch, or a frame fails to arrive, it keeps the rows joined so far ("Kept the part before the page changed.").
- **Only new rows are kept.** `ScrollStitchSession` keeps the first frame and, for each forward scroll, the strip it revealed, each in its own bitmap; a fixed footer is kept once and drawn at the end, and a fixed header shows once because it never scrolls. The stitch lets go of each strip as it draws it, so one copy grows while the strips shrink.
- **The result is capped.** It never passes 20,000 px tall ("Scrolling capture reached the 20,000 pixel limit."), nor 25,000,000 px in all, so the finished bitmap stays under 100 MB (at 4 bytes a pixel): an area wider than 1,250 px reaches the pixel guard first (17,857 px tall at 1,400 px wide). The strip that would pass either is cut to fit and the run ends. Vorssaint's other guards stay: 120 s and 512 joined strips. The pixel guard and those two end with "Scrolling capture stopped at its limit."; the 20,000 sentence is only for the height cap.
- **No window of ours is in a frame.** The run's capture filter leaves the whole app out, the island, the launcher, the guide, Settings and the editor included, whatever "Show in screenshots and videos" says, and it is built once per run, since resolving windows per frame loses the overlap. Our app is found by its pid among the shareable applications, else as the owner of one of our windows; when neither finds it the run ends with "Capture area is unavailable." rather than capture our windows. The area is snapped outward to whole pixels of its display (`ScrollingCaptureRegion`), so no frame is resampled; an area across two displays is refused.
- **The model has no clock.** `ScrollStitchSession` is handed each frame with the uptime it was taken at (a sample every 0.09 s, still after 0.22 s, one last frame and up to 0.85 s of grace after Finish); `ScrollingCaptureRun` is the loop around it, off the main actor, with the uptime and the pause injected through `ScreenshotSystem`.
- **One thing at a time, as for every capture.** While a run is on, every other Screenshots command is ignored; while the editor or another capture is open, Scrolling Capture is ignored.

### Using it

- Run **Scrolling Capture**, then drag an area, click a window, or press Return for the display, as for Capture Area. Drag just the moving area to omit static sidebars and toolbars from the result. A click-through outline (`ScrollingCaptureGuide`, the selection overlay's `dialogDimming` and `dropTarget`) stays over the area while it is scrolled by wheel, trackpad, keys or scroll bar.
- The island's rest pill shows the stop (`stop.circle`) with the stitched height in up to four characters (`980`, `1.2k`, `20k`). Finish by running the command again (its hotkey too), by clicking the stop, or by the pill menu's **Finish Scrolling Capture**; **Cancel Scrolling Capture** drops the run and copies nothing. Once Finish is asked the menu rows go and the stop takes no more clicks until the result. While an add-on has posted an island page, a click on the pill opens the island and the stop is its top row; while a meeting is carded the stop has no click, and the command and the menu still finish.
- The result goes where every screenshot goes ("Screenshot destination": Clipboard by default, File, or Clipboard and file), says "Copied" or "Saved to <folder>" as the editor does, and becomes the last capture, so Edit Last Screenshot opens it. It never opens the editor by itself, even with Edit after capture on, since the editor fits a tall image into a thin strip. A limited or partial result is still delivered, with its reason as the notice, for 4 s.

## Window

`CaptureEditorPanel` is a borderless floating panel on the stock panel recipe (`panelScrim` over `GlassEffectView`, clipped to `Theme.Radius.dialog`), sized so the capture fits in 80% of the screen under the pointer, never narrower than `Theme.Size.panelWidth` and never above the screen's visible top: the ways out on top, the tool rail on the left, the capture, and the style bar below, the rail and bar groups on frosted capsules like the Notes formatting bar. After a crop the capture is refitted to the same area, never past its natural size. It is not an island surface: the design system lets Screenshots own its capture surfaces (`notchcast/docs/design-system.md` §12). Every key goes through `AnnotationKeyAction` in `sendEvent`, so shortcuts need no focused control. Clicking away leaves it open.
