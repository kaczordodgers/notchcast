# Island shell

The shell keeps the stock `PalettePanel`, content view, first responder and palette-sized frame. Stock `show()` and key regain use the island's level through two one-line hooks. Paste-target capture, input-source sessions, focus restoration, `hide()` and cleanup execute unchanged. A separate non-activating backdrop paints the engine outline in its display's look ("Look", below) and never becomes key. Native window coordinates remain authoritative for menus, field editors, cursor rectangles, share anchors and placement readers; no content-rectangle adapter is needed.

`AppCore` owns `IslandCoordinator`. It keeps one backdrop per `CGDirectDisplayID`, shows the rest pill on the primary screen and opens the launcher on the pointer screen. Dictation can show on another display while the rest pill stays on the primary screen. A visible palette retains its display across mode changes and re-centers when that display's frame changes. Notch, island-top or backing-scale changes recreate the engine surface when no palette or overlays are visible and no frame is pending; otherwise recreation waits for their dismissal and for the pill to settle. Persisted stock placement is ignored. The backdrop is above the menu bar and the palette immediately above it. Summon and key regain write the island level synchronously. While stock sinks the palette for a modal picker, or while a visible palette sits below the island level, the backdrop hides. Modal completion lifts a palette left open through the picker back to the island level, and the rest backdrop returns after a suspended close and modal completion. The base stack pins dragging off and hides placement settings, so drop guides stay off. Compact mode uses the expanded engine state at the native compact panel size without the stock rendering outset (`IslandPaletteSurface.renderingOutset`), so the island keeps one width in every launcher state; only the Debug stock control keeps the outset. On a full-screen Space the rest pill, the meeting countdown and status stay off; a notice, a volume level, the meeting expansion, the palette or an overlay still shows, and the backdrop hides once the pill settles back. A display counts as full-screen when one of its on-screen display-wide windows shares its left edge, width and bottom edge with a window of the same app that reports `AXFullScreen`; the top edge moves with the menu bar's reveal strip. AX lists no window from another Space. The AX reads run off the main actor with a 0.25 s timeout each, on every Space change and app activation, and only the latest check applies. Window bounds alone also match a zoomed window. With no Accessibility grant, or on any AX error, the rest pill stays. Scene `full-screen` checks each state with the flag set; scene `full-screen-space` checks on the test display that a zoomed window keeps the rest pill, that a real full-screen Space hides it (kept without a grant), that a notice shows on it, that the pill settles back, and that it returns on the desktop beside a zoomed window of the same app. Not verified: a hung app, and a second display.

The engine receives fixed native sizes rather than SwiftUI content. Palette content mounts once in its stock panel, with root glass disabled and lagoon accent tint applied at the root. Stage width follows native resizing through `IslandSurface.resize`. The palette, the notch headline and the meeting expansion open through `IslandSurface.expand` (`Service/IslandSurface+Expand.swift`), which shows the new shape before resizing the stage: the engine skips a resize that leaves the shape alone without recording the new width, so a show after it saw a width change and snapped instead of springing. The DEBUG scene `expand-openings` (`Service/IslandOpeningScenes.swift`) opens glance to palette, glance to meeting expansion, meeting to palette and the notch headline live on the test display and requires each first changing frame to cover less than half its travel. `Tests/nc-Island-expand-order-test.swift` holds the first frame of each change between the glance, the meeting expansion and the palette to less than half its travel. The outline radius stays 26 points at interface scales 1, 1.1 and 1.2; content and stock internal metrics scale normally. The 1100 by 860 point host fits the 900-point-wide scale-1.2 panel. A notched screen profile derives its sensor width from the auxiliary menu-bar areas and its height from the top safe-area inset; live notch behavior remains unverified.

Mode re-show uses the same synchronous level hook. There is no level KVO or corrective origin write; the only deferred level write is the modal-completion lift. Palette, reports and questions use named levels 26, 27 and 28 respectively. Rest clicks also check palette visibility across all displays. Key-window notifications during a modal schedule one default-mode callback to refresh backdrop visibility after the nested modal loop ends, including when the palette has already closed. System accessibility-display notifications update Reduce Motion, and palette/settings observation updates the app's animation preference.

The open island carries a keyline, the one stroke the design system allows (§2): `IslandCanvas` strokes the outline clipped to itself, so one device pixel (`1 / backingScale`, `IslandKeyline.width`) sits inside and the outline never changes size, and the controller mirrors it as a `CAShapeLayer` over the palette content, under the same mask, because the palette covers the backdrop. Strength is `IslandKeyline.strength`, the outline's growth past the rest pill over a 16-point ramp, so it fades with open and close and is 0 at rest; colour is `NotchTheme.Colors.islandKeyline` (white 0.15, taken from IslandShell's 0.1488 panel keyline; none in Light), resolved against the canvas's `effectiveAppearance`, never the ambient drawing appearance, which still reads the old one at a flip; `viewDidChangeEffectiveAppearance` repaints the frame at once (`onAppearanceChange`). `AppSettings.islandOutlineWhenOpen` ("Outline when open", settings file `appearance.islandOutlineWhenOpen`, on by default) turns it off live; its row sits under "Island" in the Island tab of Settings' Notchcast section, beside "Show in screenshots and videos". `nc-Island-keyline-test` renders the canvas at 2x and pins all of it. The DEBUG scene `keyline` (`Service/IslandKeylineScenes.swift`) opens the real launcher on the test display and checks the layer sits above the content and under the panel mask, its path and stroke alpha at rest (0), mid-open, open (0.15) and mid-close, that flipping to Light mid-open must read 0 on the next frame, and that turning the setting off reads 0. It exited 1 while the colour resolved outside a drawing context, where it stayed Dark after that flip; not run live since the fix. This paragraph is the Black look; on Frosted the same line is the glass edge ("Look", below).

One engine frame callback paints the native alpha-backed outline and updates the panel content layer mask in one Core Animation transaction. Move and resize notifications update the target synchronously. WindowServer uses the painted alpha for click routing, while AppKit hit testing checks the current engine outline at event time. There is no periodic timer, pointer polling or event-routing toggle. Engine callbacks stop after settling; typing does not remeasure or animate the island.

## Verification boundary

Debug argument `--island-verify` enters a separate application delegate before migrations, normal scenes or `AppCore.start`. It requires a bundle identifier starting `app.notchcast.v2` (one channel per worker, such as `.v2shell` or `.v2pill`; no "tinycast", which the name override rejects in a helper) and a test display, pins AppKit appearance to dark and bypasses normal startup services. An independent watchdog exits with code 124 after nine seconds. The dictation cleanup scene gets 20 seconds to exercise its ten-second provider deadline. Failed expectations print to stderr and exit with code 1. The stock command-Escape event tap is disabled for this Debug argument, so making the native panel key cannot request a global event-listening grant. The caller runs the Debug binary bare inside a throwaway macOS guest, which is the isolation: nothing it writes or reaches outlives the guest.

Live checks run only inside a macOS guest (`gate pick notchcast try --guest`, then `guest up`), never on a Mac's own screen. `--island-verify` is Debug-only and `guest pr <n>` installs the Release test build, so the guest builds the PR's tree in Debug itself (`TINYCAST_BUNDLE_IDENTIFIER=app.notchcast.v2<task>`) and runs each scene with `ISLAND_TEST_DISPLAY` set to the guest's main display id (`echo 'import CoreGraphics; print(CGMainDisplayID())' | swift -`). `IslandVerification.testScreen` is the one Debug matcher: it accepts only that display, under `IslandTestDisplay`'s rule (only when `kern.hv_vmm_present` is 1, and never a built-in display), so on a real Mac it refuses every screen, a second monitor included. Without a match, verify mode refuses to run and the island coordinator lists no screen. `AppWindowController`, through `IslandVerification.keepOnTestDisplay`, ends a verify run before it creates or raises any window, re-raises included, when no test display matches, so losing the display after startup fails the run rather than putting a window on a physical screen; the `window-guard-new` and `window-guard-raise` scenes drop the display mid-run and must exit 1 on that check, and `window-guard-deferred` drops it after Settings shows with no further show, so only the raise's queued re-raise can hit the check. A guard scene that gets past the check exits 2, so exit 1 always means the guard fired. Normal Debug and Release are unaffected. Neither display capture nor Screen Recording permission is used.

At several engine callbacks the proof records both AppKit window frames and both transformed outline bounds, renders each window's own layer tree into a separate bitmap, then composites those bitmaps at their real frames over diagnostic gray. Separate buffers preserve transparency because `CALayer.render(in:)` clears its destination. This proves layer state, not WindowServer composition or presentation latency. The stack-75 gate at `74531b479` passed with 215 frame samples, maximum coordinate disagreement 2.2737367544323206e-13 points, and inspected composites for rest, open start/middle/end, compact, expand, scale-1.2 resize middle and close middle. Later stock-lifecycle scene captures also check the native panel top against the screen top. `IslandController.capture` is async and returns only after the still is taken, so a scene cannot change the pill between asking for a still and its frame.

The fix-round repeat on rebased `7bd152eaa` recorded 220 samples with the same maximum coordinate disagreement, but with synchronous layer capture on, its first changing outline arrived at 121.659 ms versus stack-75's 64.707 ms. A capture-off rerun (timestamps only, three alternating runs per side) settled it: median first post-open callback / first changing outline 17.463 / 44.069 ms at `2c6faabe8` versus 15.931 / 41.882 ms at `74531b479`, +2.2 ms, under one 75 Hz frame, so the fix round did not delay the open; the capture pause caused the earlier gap. This measures main-thread callback and layer state, not WindowServer presentation. Frame logs are in the worker's scratch `timing/` directory.

The unchanged keyboard harness passed live: `PASS: palette keyboard contract (122 checks)`. `Tests/nc-Island-layout-test.swift` compiles the shipped pure geometry source and checks screen/notch/scale/position anchoring and flipped/native coordinate transforms. `Tests/nc-Island-position-test.swift` checks the Island position drops (below). `Tests/nc-Island-screens-test.swift` checks explicit display selection, stable retention across reorder and disconnected-display fallback. The fork stack supplies the engine pin, look tokens, dark/drag pins and unchanged keyboard harness. Upstream harnesses also run locally.

Capture, scene, latency, sample collection and CPU timing implementations compile only in Debug. Release retains trivial disabled-entry stubs. A Release compile and demangled symbol scan check that verification implementations and per-frame measurement storage do not ship.

Latency uses the prototype protocol: five alternating stock/island runs, 60 insert/delete events each after warmup, actual local app-index rows, and a clock from in-process `NSEvent` delivery through the updated root body, native layout/display and `CATransaction.flush`. This is CPU input-to-frame-submission latency, not input-to-photon latency. The final measurement at `8cb325a08`, before the later naming rebase and this fix round, was stock median 28.592 ms / p90 40.445 ms and island median 29.073 ms / p90 40.290 ms (300 samples each, 226 indexed apps). The 0.481 ms median difference is smaller than run-to-run variation; this does not establish a regression. Callback intervals were median 16.676 ms / p90 17.276 ms, despite the test mode reporting 75 Hz. Whole-process CPU accumulated during callbacks was median 2.012 ms / p90 3.218 ms, including concurrent process work rather than exclusive engine CPU. Callback interval and CPU samples exclude PNG capture. There were zero engine animation callbacks during all five timed typing sequences. The control uses the same instrumented Debug binary with island placement disabled and native root glass restored, rather than a pristine upstream binary. These numbers are historical measurements, not a fresh benchmark of this fix round. Native keyboard scenes cover typing, arrows, Enter, Escape through the stack then close, Tab and form focus; menu scenes cover Command-K.

## Questions and reports

Native dialog and HUD panels retain their stock presenters, sizing, responders, continuations, fades and dwell tasks. A question uses the visible palette's display or otherwise the cursor display. A message report honors its presenter's supplied screen, even if a different display was active previously. Reports stack below the question and palette on their own display, at a lower level than questions. The backdrop grows to contain these native frames. Native `orderOut` hooks release their reserved frames synchronously, including fade completion; `willClose` also removes entries. `IslandOverlayLayout` receives Theme spacing as injected geometry parameters. Its harness checks preserved accessory size and non-overlapping placement, including negative screen origins and notch offsets.

The second question still cancels immediately. Live native events exercise volume arrows and Enter, multiline text editing with Return and Command-Return, and Escape cancellation. A progress report replaced by completion retains its HUD panel, never hides the palette and never steals the question's key window. The stock 2.4-second message dwell and `extend()` remain intact. Volume uses no HUD: its commands show an island level through `islandPresenter.showLevel` with a 1.5-second dwell, drawn in the resting pill, or as a band in the report slot while the palette or a question is up (see Presentation API). `VolumeHUDController` and its view stay in the tree, hidden and unreferenced, so upstream edits to them never conflict. Dialog and message surfaces, and the unreferenced volume view, use `NotchTheme.Colors.islandSurface`; their content and tone decoration remain. Only a settled rest pill, or a settled hover-opened meeting view, takes a click. Expanded backdrop margins cannot switch modes or cancel a question. The backdrop sets `hidesOnDeactivate = false`.

## Island position

Island position (`AppSettings.islandPosition`, settings file `appearance.islandPosition`, also in settings backups; its row, "Position on displays without a notch", sits under "Island" in the Island tab of Settings' Notchcast section after "Outline when open") places the rest pill on a display without a notch: `topEdge` (default) at the screen's top, `menuBarCenter` centred in the menu bar, `menuBarBottom` flush with its bottom. The menu bar height is `frame.maxY - visibleFrame.maxY` per screen, read at each `IslandController.configure` and again after every Space change (`refreshMenuBar`, which reconfigures only when the top moves), because a full-screen Space hides the bar without a screen-parameters change. `IslandPosition.drop` rounds the gap down to whole points: on a 30 pt bar with the 24 pt pill, 0, 3 and 6 pt. Without a notch the island window's x also rounds down to whole points (`IslandLayout.window`), so an odd-width screen cannot leave the pill on a half point (a 1367 pt screen put it at 635.5); the palette anchor reads `IslandLayout.openingX`, so the panel and the pill keep one centre line, and a notch keeps the unrounded centre. A hidden menu bar (no gap, including on a full-screen Space) or one shorter than the pill keeps the top edge. A notch ignores the setting. `IslandLayout.applyTops` (`IslandLayout+Engine.swift`) hands the engine one top for idle, compact and expanded, so the pill never jumps as it grows; `contentTop` and `openingTop` put the palette, questions, reports, menus, the meeting expansion and headlines at that same top. `IslandCoordinator` observes the setting and rebuilds; a changed top is part of `IslandSurfaceConfiguration`, so the engine surface is recreated, deferred while the palette or an overlay shows, as for a notch change, and while any frame is pending (`IslandFrameSource.isIdle`), because a rebuild starts at the rest pill and would snap a running open, close, expansion or glance. While deferred, the controller keeps the live surface's layout, so the mask, the open panel and overlays stay on the old top until `closed` applies the new one; `closed` starts the close before it retries, and `IslandFrameSource.didSettle` retries once the last frame has drawn. A settled glance or notice has no frames pending, so it is rebuilt at once and grows again from the rest pill. `Tests/nc-Island-position-test.swift` pins the three drops, rest/open/overlay tops for each, the engine's equal idle, compact and expanded tops through the shipped `applyTops`, the engine's content top against the launcher, whole-point pill and panel x on odd-width and negative-origin screens, the notch ignoring it, the held configure applying once (`IslandHold`, which `didSettle` and `closed` release through `applyPending`), and the pure surface decision (`IslandSurfaceConfiguration.update`: a moved top waits while animating, an unchanged one is kept, the first build never waits); the frame tally and `IslandController` itself are not harness-covered. Not verified: the Space refresh live, because the app may not run on a physical display here.

## Hover

Resting the pointer on the island opens what it shows. `IslandHover` (`Model/`) is the state machine: the open clock (`openDelay`, 0.1 s) starts when the pointer is in the zone with no mouse button held, no menu open and the island settled, and opens the island when it runs out; leaving starts the close clock (`closeDelay`, 0.1 s; both as fast as the pointer allows) and coming back cancels it; a button held while open keeps it open and the close clock starts at release. The launcher, a question or report, a modal or a full-screen Space close it at once and start nothing; the island's own menu freezes it. "Open on hover" (`AppSettings.islandOpensOnHover`, settings file `appearance.islandOpensOnHover`, also in settings backups, on by default; its row sits under "Island" after "Outline when open") turns the open clock off and closes a hover-opened view. A pin (`IslandHoverTracker.togglePin` for an island page's Command-P, `pin` for a primary click on the island) opens and holds the island until it is unpinned, a click lands outside the zone or the launcher opens; hover never takes the keyboard; a click on the island or on a page pins and makes the page panel key, so Command-P and the page keys work from there (Pages, below). `IslandHoverZone` is the island's outline in screen points, plus, below the menu bar only, `Theme.Spacing.xxl` (20 pt) further down and `Theme.Spacing.lg` (10 pt) past each end, so a bare notch needs no aim at its lower edge while the menu items beside it stay the menu bar's. It tests each rect with `NSMouseInRect`, as `NSScreen.underCursor` does, so the screen's top pixel row, where the pointer's y equals the rect's `maxY`, is on the island.

`IslandHoverTracker` (`Service/`, owned and started by `IslandCoordinator` as `hover`) watches the pointer with a global and a local `NSEvent` monitor for moves, drags and clicks (no Accessibility grant; no polling) and, over the island's own window, through `IslandCanvas`'s tracking area (`.activeAlways`, entered, exited and moved, wired as `canvas.onPointer`), so a move there needs neither monitor (delivery not verified live), and reads the resting controller's `screenShape` and screen. The monitors run only while "Open on hover" is on or a pin waits; a click in another app or in a Notchcast window outside the zone dismisses a pin, a click on the island's own menu does not. It refreshes on settle (`IslandController.onSettle`), palette, question and setting changes, the island menu closing (`IslandPillMenu.hide`), a full-screen Space change, a modal ending and a display rebuild, so no input change waits for the next pointer move. Its `World` (clock, input, monitors, wake-up) is injected; `IslandHoverTracker+Core.swift` binds the real one, and `Tests/nc-Island-hover-test.swift` drives the tracker with a fake one and guards those refresh calls in the source text, the settle and `observeVisibility` ones included. Only the resting display's island hovers. When it opens or closes it calls `IslandPresenter.hoverChanged`, which shows `IslandHover.notice`: a showing notice holds its dwell (paused like an unseen one) and, on a notch, brings a compact download's title out as the headline; with no notice, the newest status's name shows on the notice line (headline below a notch, `IslandNoticeArt` in the pill), without an announcement; a meeting glance opens the shipped meeting expansion without spending the automatic one, and one that arrives over a hovered status name replaces it (`IslandCoordinator.showGlance` sets the glance before `IslandPresenter.meetingChanged` recomputes the notice; `Tests/notchcast-addon-notice-queue-test.swift` runs it on the shipped presenter); a level changes nothing. When any add-on has posted a page, hover opens the pages instead of the notice line, headline or glance; on a bare island (no page, notice, status or meeting glance) hover and a click open an empty Home (Pages, below).

Every engine spring runs `IslandController.motionSpeed` (4) times faster through the frame clock's `timeScale`, so opens and closes reach 99 % of their travel in about 90 ms (the meeting view's return in about 200 ms), and the first frame still covers under a quarter of the travel, so nothing snaps. `Tests/nc-Island-hover-test.swift` checks the delays with an injected clock, pass-through, leave and return, buttons, covered, the setting, the pin, the zone and the hover content (model proof). `nc-Notchcast-island-audit-render-test` renders the `884-*` hover states in both forms (`NC_AUDIT_LOOK=frosted` for Frosted). Not verified: hover on a real notch or display (no live hover scene exists), the delays' feel, the global monitor under Secure Input, and the island's own menu anchoring under an open meeting view.

## Look

## Screen capture

The Island tab of Settings' Notchcast section has "Show in screenshots and videos" (`AppSettings.islandShowsInCaptures`, settings file `appearance.islandShowsInCaptures`, on by default). With it off, every untitled Notchcast window (the island, its HUDs, palette, questions and reports) is hidden from screenshots, recordings and screen sharing; with it on, none is. Titled windows (Settings, Notes, About) are always shared, like any app's: `IslandCaptureSharing.sharing(for:captures:)` keeps them `.readOnly` (harness `nc-Island-capture-sharing-test`). `IslandCoordinator.applyCaptureSharing` sets the `sharingType` of every other window in `NSApp.windows` to `.none` when off and `.readOnly` when on, on each rebuild and live through its own observation of the setting, started with the island (so scenes run the shipped path); `IslandPillMenu` carries it to the menu panel it observes, open or next opened. A window made later gets it before it shows when it passes through the island (`anchor` for the palette, `IslandOverlayController.placeQuestion` and `placeReport`), and any other window when it first becomes visible (`NSWindow.didChangeOcclusionStateNotification`, about one frame after it shows; a new window starts `.readOnly`, so only off waits that frame). Once a window is set to `.none`, AppKit's `sharingType` getter keeps returning `.none` (seen on Darwin 27.2) while WindowServer does take `.readOnly` again, so check WindowServer's `kCGWindowSharingState`, never the getter. So a window that has been shown again is hidden by replacing it, and turning the setting off closes what would keep it: the pill menu, if its panel or any backdrop was shown again while it stayed open, and the launcher, if a backdrop must be replaced; a closing menu stays capturable for its fade-out. Notchcast's own Screenshots follow the same state: `ScreenshotExclusion` leaves out only its selection surface and our windows whose `kCGWindowSharingState` is none, so Settings is captured and pickable and the island shows exactly when this setting says. Scene `capture-sharing` (`IslandCaptureScenes.swift`) reads `kCGWindowSharingState` on every visible Notchcast window (titled ones must read shared) and the open pill menu at the default, after turning it off with the menu open, after reopening the menu, after turning it back on with the menu open, after turning it off again with that menu open (the menu must close and every window be replaced), with the menu closed, with the launcher and a report shown while off, and with a titled window ordered front while off. On Darwin 27.2.1 both `screencapture` and a ScreenCaptureKit display capture leave out a `.none` window, and flipping a plain panel between `.none` and `.readOnly` in place takes effect each time; real screenshots of a Debug build with the launcher open showed the launcher, a report and a question absent while off and present while on. Not verified: a screen recording, and the scene since the palette, report and every-window checks were added.

## Presentation API

Code outside `Features/Island/` reaches the island only through `AppCore.islandPresenter`, an `any IslandPresenting` (`Service/IslandPresenting.swift`) that add-on coordinators take in their init. Its values (`IslandLevel`, `IslandNotice`, `IslandStatus`, `IslandMenuRow`, and `IslandPage` for `setPage`, see "Pages") are Foundation-only in `Model/IslandPresentation.swift`. `showLevel` is the one generic level call for every source: Tinycast volume now, add-ons later (hardware volume keys, brightness, keyboard backlight). `IslandLevel.source` is the caller's own parameter, and nothing in the presenter or its types is volume-specific. The shipped `IslandPresenter` renders levels, notices and status on the resting pill, in the same order as the accessibility value: a level, else a notice, else the meeting glance, else the status glyphs. `setMenuRows` adds rows to the pill menu, in one section between the feature rows and Updates, Support, Settings and Quit: owners in their first registration's order, which a replacement keeps, rows in array order, an empty array removing the owner. The title is the caller's and never localized; the menu filter and keys apply to it, and choosing it closes the menu before `onSelect` gets its id. Each row gets a check column, filled when `isChecked` is true and empty otherwise, so it lines up with the stock rows' icons. Rows set while the menu is open refit it, and the keyboard cursor stays on its row, known by owner and id rather than title, or on its index when that row is gone. The DEBUG scene `pill-menu-rows` (`Service/IslandMenuRowScenes.swift`) checks order, replacement in place, the cursor kept, removal, filtering and selection on the test display. `IslandNoticeArt` (`Service/IslandNoticeArt.swift`) draws a notice in the wings as a still progress ring (no spinner) while its `IslandProgress.fraction` is known, else its `swatch` (`IslandSwatch`, sRGB, under `IslandCover.edge`) when it has one and is not a failure, else its symbol, tinted `Theme.Colors.destructive` when `isFailure` is set; without a notch its text follows in `islandGlanceNSFont`, truncated to the glance wings, and on a notch only the bare percent, rounded down, sits right of it. On a notch a notice whose `isHeadline` is true (every notice without progress, and titled progress until its first dwell is spent) draws as `IslandHeadlineArt` instead (design system §10): `IslandCanvas.show` takes the notch width, and the controller grows the engine's `.expanded` surface with the headline's size as its bottom, under the content key `notice.<id>`, through `IslandSurface.expand`. The canvas fades each grown part by its own height (the grown height over the headline's, else over the meeting expansion's), draws the line only over the outer half of that travel, and keeps the old line while the island contracts, so it fades out rather than vanishing; it draws no line while the palette or a report owns the grown shape. `isResting` counts the grown headline as rest, so a notice's tap still works while it is open. `IslandStatusArt` draws the status glyphs in a row, each inked by its `IslandTone` when set (`IslandTone.color`, as a Home line's glyph is) and with at most four characters of its `text`, centred and never narrower than the rest pill, or right of a notch; when the row is wider than its wing it drops the oldest statuses first, so the newest, which the pill's tap acts on, always shows, and the accessibility value still lists every label. Notices stack in `IslandNoticeQueue` (`Model/`), newest on top: the pill shows only the top one, and only its dwell runs, for `IslandNotice.dwell`: the poster's `seconds`, or by default the stock message HUD's 2.4 s, and 4 s for a failure (design system §10), while a progress notice stays until its caller ends it. Titled progress (`IslandProgress.headline`, the default) first runs one `IslandNotice.messageSeconds` dwell as a headline; when that runs out the queue clears `headline` and the notice stays, compact, until its caller ends it. A repost while it headlines keeps what is left of that dwell, whatever its text; once compact, the id stays compact until it is ended, and only a new id or an end followed by a new post headlines again; untitled progress (`headline: false`) is compact from the start. Whatever keeps it unseen pauses that dwell: a level (in the pill or as a band), the palette or a question over the pill, or no resting pill at all (no display); it resumes with what it had left once the notice is seen again. The presenter observes the palette and question while a notice is live, and every rebuild calls `restingChanged()`. When the top notice expires or is ended, the one under it returns with the dwell it had left; ending a covered notice drops it without touching the top, and reposting an id keeps its place in the stack and restarts its dwell, except a progress, above. `Tests/nc-Island-notice-test.swift` checks these rules and the announcements (model proof), with the 4 s failure default. `Tests/nc-Island-canvas-test.swift` checks that an ended headline never draws inside the meeting expansion, that a notch change moves the text between the headline and the pill, the rounded-down percent, and that a long headline stops at `NotchTheme.Size.islandHeadlineMaxWidth` (320 pt) and truncates at its tail while a shorter one keeps its natural width. The DEBUG scene `notice-unseen` (`Service/IslandNoticeScenes.swift`) posts a 0.6 s notice under the open launcher and another with no display, waits 1 s, and requires each to show once the launcher closes or the display returns, then run out its dwell (rendering proof). A notice also holds back the meeting expansion, which starts when the notice ends if the window is still open, and a notice posted mid-expansion cuts it short, as a level does. The island window's canvas is one accessibility group labelled "Notchcast" whose value is what the island shows now, in presenter order: the level as "<label>, <percent>", else empty while the palette covers the pill, else the notice's `spokenText` when set, otherwise its text, else the meeting glance as "<title>, <countdown>", else the status labels, empty at rest; pressing it is the pill's click. The `onTap` given to `post` and `setStatus` replaces that click on the resting pill: the live notice's tap, else none under the meeting glance, else the last status's tap; with none, or whenever a page exists (`IslandPageDeck.opensOnClick`), the click opens and pins the island (`IslandCoordinator`, "Hover"), and the tap moves to the notice row on the open page (see "Pages"). The value refreshes on every `frameChanged`, so it hides when the palette opens and returns when it closes without a new announcement. A notice is announced once per id and text when it first reaches the top, so a notice returning from under a newer one stays quiet; a progress is announced once as it starts, not as its numbers or phase text change, and a new progress on the same id after a result speaks again; a notice's `spokenText`, when set, is said instead of its text, on the pill and on its row in the open island; levels and status only change the value. The DEBUG scene `island-ax` (`Service/IslandAccessibilityScenes.swift`) hit-tests the pill through in-process AX and checks role, label and value at rest, status, glance, notice and level, and counts announcements through `IslandVerification.announcements`; it also unplugs and replugs the display and requires the old pill cleared, the new resting pill carrying notice and status, and no new announcement, because every rebuild hands them over through `IslandPresenter.restore` without posting; when VoiceOver, Switch Control or Accessibility Inspector runs it prints `NOT VERIFIED: other AX client` and skips the reads. A level shows in the resting pill on the island's screen, or as a band in the report slot while the palette or a question is up. `IslandLevelDwell` (`Model/`) keeps it 1.5 s past the last call, so a burst of repeats is one presentation, and its `placement(palette:question:)` picks pill or band. The presenter observes `palette.isVisible` and `isShowingDialog` while a level is live, so opening or closing either mid-dwell moves the level between pill and band without a new presentation or a restarted dwell. `Tests/nc-Island-level-test.swift` checks those rules and the outlined zones past 0...1 (model proof). The DEBUG scenes `volume`, `volume-palette` and `volume-palette-open` (`Service/IslandVolumeScenes.swift`) check pill, band and the mid-dwell move live on the test display (rendering proof). `Tests/nc-Island-presenter-test.swift` holds `RecordingIslandPresenter`, a fake that records each call in order, and checks that it clears status, menu rows and notices.

A live notice adds three values, each nil or off by default so every other notice draws as before (#960). `IslandNotice.meter` is levels, 0...1, drawn as four bars in the mark's place (before the ring), sampled evenly from however many levels it holds, each the song meter's floor plus its level; while the canvas is `still` (Reduce Motion, Show animations off) the mark is the notice's symbol instead. `IslandProgress.readout` is a short live value: beside a notch it takes the percent's wing, and `IslandNotice.line` (the readout, two spaces, the text) is what the wings without a notch, the headline below a notch and the open page's notice row draw. A readout is measured by its shape, every digit as `0`, so a ticking clock resizes the pill only when it gains a character. `IslandNotice.quiet` keeps a plain notice beside a notch as its glyph instead of a headline; hover lifts it. `holdKeys(for:onFocus:onKey:)` lends the keyboard while the caller's notice lives. `IslandKeyHold` (`Service/IslandKeyHold.swift`) anchors a clear one-point non-activating panel at the notice's pill. `place(notice:on:)` picks a display for a notice and its key panel, with the resting pill as the fallback. Ending the notice or letting it expire clears the placement. The panel confirms it became key and forwards non-repeat Return, keypad Enter and Escape as an `IslandHeldKey`. If acquisition fails or the panel resigns, it tries once on the next main-actor turn and reports whether it has focus. `releaseKeys()` or the notice's end cancels a pending attempt and returns the keyboard. A presenter without a key panel reports focus unavailable. `Tests/nc-Island-notice-test.swift` checks the lease and `Tests/nc-Notchcast-dictation-island-focus-test.swift` exercises the panel during dictation. The dictation seam: `DictationPanelController.stand` returns from `show()` before it sets `state.phase = .listening` and zeroes `state.levels`, so a stand-in resets both itself; `DictationCoordinator.didReset` hears every session end, false on a cancel or a failed start and true on every other end, including no speech and a transcription error.

## Dictation

A dictation session shows on the island, never in stock's capsule (#960). `DictationIslandCoordinator` (`Features/Notchcast/`, beside `NotchcastGlobeTrigger`), owned and started by `NotchcastCore`, so neither `AppCore` nor DictationExtras names it, sets three hooks once: `DictationPanelController.stand`, so stock's `show()` builds no capsule and the stand-in resets the capsule's `state.phase` and `levels` itself; `DictationCoordinator.didReset`; and a wrap of `DictationCoordinator.showMessage` that keeps stock's closure for whatever the session does not take. It follows the stood-in controller's `state.levels` and `state.phase` with `withObservationTracking`, re-armed after every change while the session records or transcribes. A cancellable one-second tick reads the latest levels during recording so the clock advances even with silent input. `DictationIslandSession` (`Core/Model/`, Foundation only) is the state machine and `IslandNotice(dictation:)` the table: one notice id, `dictation`, reposted as the state changes. Recording is a titled progress with a four-bar `meter` (bar `i` reads band `i` of stock's 21 sampled evenly, each in eight steps), the elapsed `m:ss` as its `readout` and "Return to Paste · Esc to Cancel" (Copy for a copy-only destination) as its text, spoken once as "Recording dictation, Return to finish, Escape to cancel"; it reposts when a bar's step, the elapsed second or keyboard availability changes. Without key focus the notice and its spoken value say "Recording dictation". Transcribing (`waveform`) and Cleaning Up (`sparkles`) are untitled progress, so beside a notch they keep to their glyph. A result is a plain notice: Pasted and Copied a quiet `checkmark`, No Speech Detected `mic.slash`, Pasted Without Cleanup, Copied Without Cleanup (copy-only), Couldn't Paste, Some Text Wasn't Pasted and Dictation Failed red failures. Stock's three report sentences ("No speech was recorded", "Couldn't paste dictation into this app", "Couldn't paste some dictation into this app") are taken by text; apart from the missing cleanup model report, other text is Dictation Failed and stock's report still shows under the island. `didReset(true)` waits one main-actor hop before it picks the result, so the report stock raises right after `reset` in the same turn is counted. It also sets `DictationExtrasCoordinator`'s `cleaningUp`, `cleanupFailed` and `delivered` hooks (no-ops unset), so a cleanup failure in `clean` shows as Pasted Without Cleanup (Copied Without Cleanup for a copy-only destination) unless the island is covered; a paste failure stock reports still wins over it. A new session ends the last result's notice before it posts, so a matching result is announced again. Covered (the launcher or a question up as the session ends) drops the result and lets stock's sentence through; a cancel ends the notice at once. The keyboard is the key hold's from the stand-in until the text is final (`didDictate`) or the session resets: Return calls the controller's `onAccept` (stock: paste raw, no cleanup), Escape `onCancel`. A missing cleanup model shows as No Cleanup Model · Pasted Raw or No Cleanup Model · Copied Raw. When the island is covered or no session can take it, the missing cleanup model uses the original HUD sentence. Missing transcription models and capture start errors still use stock's reports. Refusing the microphone can start a silent session, as in stock. `Tests/nc-Notchcast-dictation-island-test.swift` checks the state machine and that stock's three sentences still stand; `Tests/nc-Notchcast-dictation-island-render-test.swift` renders every closed state as `960-*` and `nc-Island-pages-render-test` the open rows as `960-open-*`; the Debug scenes `dictation` and `dictation-notch` (`DictationIslandScenes.swift` beside the coordinator, a simulated 185 × 32 notch) drive the coordinator with an injected clock and levels, no microphone, and send a real Return and Escape to the app's own pid through the hold.

With more than one display, dictation uses the display holding the most area of the captured paste target's frontmost on-screen window. An editor in Notchcast gives its own window directly. With no matching window, it uses the display under the pointer, then the primary display. The one-second recording tick and the transition to Transcribing recheck the same target. The notice and key panel follow it, and the result stays on the display where recording stopped while it remains connected. A non-resting pill appears for the notice and hides after it settles. The app reads window geometry from Quartz without requiring Screen Recording access.

`nc-Notchcast-typing-display-test` covers window order, overlapping displays and fallbacks. The Debug scenes `dictation-away` and `dictation-away-notch` inject a target on a non-resting display to check visibility, key panel placement, Return, Escape, and dismissal after the result. Not verified: a second display, a real notch and active menu bar behavior while the key panel holds focus.

## Pages

The open island shows pages (look in design-system.md §17). An owner posts its page with `IslandPresenting.setPage(_:id:onAction:)`, an `IslandPage` (`Model/IslandPresentation.swift`: title, glyph, `order`, `badge`, one Home `line` and its `blocks`), and nil once it has no data; `onAction` gets the id of a button or row, and `IslandPage.refreshAction` for Command-R. A click on a Home line opens that page's tab, unless the line sets `IslandPageLine.action`: then the click sends that id to `onAction` instead (the Day page's calendar line opens My Schedule this way, decision 946-7). Order convention: Agents 0, Player 10, System 20, Day 30, so adding a page is one `setPage` call from the owner's module. `IslandPageDeck` (`Model/`) is the pure model: tabs (Home plus each page, or the single page alone with no tab bar), the selection, Home's line order (badged first), arrow, number and swipe moves (each stops at either end), `IslandPageKey` and the size rule `outline`. `IslandPresenter` owns an `IslandPageHost` (`Service/`), which keeps the deck and draws `IslandPagesView` (`UI/`) in its own clear `IslandPagePanel` at the palette's level, hung from the resting island's `openingTop` at `openingX`. The panel joins `IslandController.page`, which grows the outline to the panel's size through `surface.expand` (content key "page"), masks the panel to the outline as it does the palette's, and stops the rest art and hover pills from drawing beneath it; while a page is up the canvas's rest click (`canOpen`) opens nothing, because the page panel takes those clicks: a plain click pins, and a right click or a Control-click goes to the canvas's `onMenu`, so the island's menu stays reachable by mouse (`IslandPagePanel.sendEvent`). The outline is never taller than the island's host canvas below the notch (`NotchTheme.Size.islandHost.height` less the content top). Closing empties the hosting view, so a page's timeline stops ticking.

Hover gives pages priority: `IslandPresenter.hoverChanged` opens the host first, and the notice line, headline and meeting glance show on hover only when no page exists. On a bare island, with no page, notice, status or meeting glance, hover and the click's pin open Home anyway (`IslandPageDeck.opens(glance:)`), which then holds only "Nothing to show" in `textTertiary`, the menus' empty state (design-system.md §17), so the island always answers the pointer. Each hover opens Home again (946-2). A click on the bare resting island pins it (`IslandCoordinator`'s `hover.pin()`); while a page exists `IslandPresenter.tap` is nil, so the click opens the first tab even while a notice or status with its own tap shows. What the pill shows (`IslandHover.notice`, the live notice, else the last status unless the meeting glance shows) reaches the host through `IslandPageHost.show` on every `noticesChanged` and `setStatus`, and `IslandPagesView` draws it as the first row of the open page on every tab (`IslandPageDeck.notice`, a `row` block), a button running that notice's or status's own tap when it has one; so no page hides a notice and no tap is lost, with "Open on hover" on or off. `IslandPageHost` makes the panel key once a pin begins (`IslandPageFocus`: the first render after the pin, a click on the panel, Command-P), never on a repost while pinned, so a page update never takes the keyboard from another app; with "Open on hover" off the pages and their keys are one click away. A click on the panel pins the island too (`IslandHoverTracker.pin`) and, the panel being able to become key, the keys reach it: left and right arrows, 1 to 9, Escape (`IslandHoverTracker.dismiss`; `IslandHover` keeps it closed until the pointer has left the zone and come back), Command-R (the page's refresh, every page's on Home) and Command-P (the pin). A horizontal two-finger swipe turns tabs (`IslandPageSwipe`, `Model/IslandPageSwipe.swift`, adapted from Vorssaint's section scroll, GPL-3.0-or-later, listed in `notchcast/licenses/borrowed/Island.txt`): 24 points turn the first tab, a drag that keeps going turns one more every 80, turning back starts over, momentum after the lift is ignored, and a sideways wheel notch turns one. A command or hotkey opens a given page with `IslandPresenting.showPage(id:)`: `IslandPageHost.showPage` keeps the asked tab, pins through `IslandHoverTracker.pinWhenUncovered`, which waits up to `pinWait` (2 s) for the launcher the command ran from to go, and picks that tab when the pin opens the island, dropping it if the wait ran out, so a later plain hover or click-pin still opens Home; on an island already open it picks the tab and pins at once, and while that page shows a second call closes it, as Escape does. A page posted after it went away while pinned never takes the keyboard again, since only a close resets `IslandPageFocus`. The Player page (`IslandPlayerPage`, `Model/IslandPlayer.swift`) is built from `IslandNowPlaying`; its source stays behind `IslandPlayerSource` (`Service/IslandPlayerSource.swift`, one `perform` call), so another source can replace Spotify's (`SpotifyPlayerPage`, fed by `SpotifyModule.onPlayback`, its cover fetched once per song through the module's private Web API session, https only, at most 4 MB) without touching the page.

A page's owner refreshes its data only while that data is on show (decision 946): `IslandPresenting.watchPages(id:onChange:)` calls `onChange(true)` when the island opens on Home or on that owner's page, `false` when it closes or another page's tab is chosen, once per change, and nil removes the watcher. `id` is the `setPage` id. A watcher with no page posted counts as on show whenever the island is open, hover or pin, so it can fetch and post its first page; registering while already on show is told `true` at once. `IslandPageDeck.shows` is the rule and `IslandPageAudience` (`Model/IslandPageDeck.swift`) the once-per-change bookkeeping; `IslandPageHost` runs it after every open, close, tab change and `setPage`.

Two block kinds hold cards (`IslandCard`: a title, an optional `IslandCardTag` chip, `IslandCardMeter` bars or one notice, hollow, dimmed, a caption, one VoiceOver sentence): `columns`, titled columns in fixed slots, and `cards`, a titled row four across. `IslandCardSlots` (`Model/IslandCardSlots.swift`) is the slot rule: never fewer than three columns, a full card as tall as the tallest full card in the block, a hollow card half a slot less half the gap, a card never leaving its column; a row's cards share the tallest height and wrap past four. `IslandPageCards.swift` (`UI/`) draws them at the launcher panel's width, so a page of cards is as wide as the launcher whatever it holds.

The Player page (`IslandPlayerPage`, `Model/IslandPlayer.swift`) draws one `media` block: cover, title and artist with the like heart when the player knows it (`IslandMedia.like`; dimmed, unclickable and read as "Checking Liked Songs" while `likePending`), the running time on a bar a click or drag seeks when `seekable` (the fill follows the drag, one seek on release), the transport, a volume bar when `volume` is set (`live`: sends at most every 100 ms while dragged, the held value once still, the exact one on release), and "Up Next" beside it, a column of plain rows, while anything is queued. A bar with an action sends `IslandMedia.action(_:_:)`, "media.seek:<fraction>" or "media.volume:<fraction>", through the page's one `onAction` string, and VoiceOver's increment and decrement move it; `IslandPlayerAction(id:)` reads every id the page sends back, including the page keys. The page sets `takesKeys`, so `IslandPageDeck.pageAction(for:)` hands it space and the arrows ("key.space", "key.left", …) instead of the deck.

`Tests/nc-Island-pages-test.swift` covers the deck, keys, swipe, sizing, the on-show signal, the notice row and click rule, the key-once focus rule the Player page with injected dates and the card slots; `nc-Island-page-host-test` runs the shipped `IslandPageHost` against a screenless island, so the bare island's Home, the signal's calls on open, close, `setPage` and `watchPages` the notice row's tap and `showPage`'s waiting pin and chosen tab are checked and no window is built (a tab change's is not, nor `makeKey` itself, which needs a real panel); `notchcast-addon-notice-queue-test` checks that `watchPages` reaches the host; `nc-Island-hover-test` covers Escape staying closed under the pointer and `pinWhenUncovered` pinning in time and never after; `nc-Spotify-module-test` drives Spotify's page with a fake transport; `nc-Island-pages-render-test` renders the acceptance set (one, three and five pages, Home and a page, the approved Agents board as `975-agents-slots-*` and one Mac alone as `975-agents-alone-*`) in both forms on Black and Frosted to PNGs, which `main-harnesses.yml` uploads as `island-renders-<shard>`. Not verified: any of it live (hover, `showPage` from the launcher and from a hotkey, the click pin, the click on the bare island and the keys after it, the menu click on a page, the notice row and its click, key focus without activation and after a repost, the swipe, the outline's spring to a page, a real notch), VoiceOver on the tabs, and the cover fetch against Spotify.

## Song glance

The song a player loads rests in the pill. `IslandPresenting.showPlayer` posts the Player page and, through `IslandPresenting.setSong` (shipped by `IslandPresenter`), the song; nothing in it names a player. The presenter strips the running time first, so a position sync never redraws the pill. `IslandCanvas` draws it as `IslandSongArt` (`Service/IslandSongArt.swift`) below a level, a notice and the meeting glance and above the status glyphs, so a meeting glance wins and the song returns after it. On a notch the wings hold only the cover (left, `xxxl` from the wing end) and the meter or a pause glyph (right); without a notch the pill also carries "title · artist", which `IslandSongOverflow.widen` lets grow up to `islandHeadlineMaxWidth` per side and then truncates, and `.scroll` keeps the glance-wing cap and scrolls the line (`IslandSongLine`); `compact.maxSlotWidth` is `islandHeadlineMaxWidth`, and every other art caps its own wings at `islandGlanceWing`. `IslandCover` draws the cover, a `keyCapFill` tile with `music.note` while it loads, and a 1 pt `islandEdge` line inside every cover. The meter is `IslandEqualizer.levels(at:playing:)`, four bars as a pure function of time with no audio tap; the canvas runs a `CADisplayLink` at up to 30 fps only while a meter or a scrolling line moves, never under Reduce Motion or with Show animations off (`IslandCanvas.still`). On a notch a new song id, never the first one seen, grows the pill through the meeting expansion's two lines for 2.4 s, cover where the meeting shows its glyph (`IslandSongChange`, `IslandController.songChange`); a level, a notice, the meeting glance or expansion, or the open island cuts it and it does not return. The expansion's text stops at `islandHeadlineMaxWidth` and truncates, for a meeting too. The accessibility value reads "title, artist, Playing" or "…, Paused" after the meeting glance. `Tests/nc-Island-song-test.swift` checks the line, marquee, meter, song change and VoiceOver value (model proof); `notchcast-addon-notice-queue-test` runs the shipped presenter's song change against a manual clock and checks that `showPlayer` hands the song to the pill; `nc-Notchcast-island-audit-render-test` renders the glance and the change in Black and Frosted, both forms. Not verified: the meter's frame rate and CPU on a real display.

## Meeting expansion

When Calendar's carded meeting enters its join window, the resting pill grows once to two lines, glyph and title over the grey countdown, for 6 s, then settles back to the glance. `IslandMeetingExpansion` (`Model/`) decides it: once per occurrence, keyed by event id and start, in memory only and pruned to the carded meeting, so a new occurrence of the same event expands again and a relaunch can expand once more. Priority is question > palette > level > notice > expansion > rest > empty. An expansion waits while a level or a notice shows and starts when it ends; a level or notice arriving mid-expansion cuts it short and spends it; a palette or question open at window start spends it, so it never replays when they close. `IslandPresenter` owns it: `IslandCoordinator.showGlance` hands it the glance's occurrence through `meetingChanged`, it runs at most one token-checked expansion task, and it sets `IslandController.expanded`, which the controller draws as the engine's `.expanded` surface at the glance's width or wider. Motion follows the existing path, so Reduce Motion and Show animations apply. `IslandCanvas` cross-fades the glance and the expansion inside a transparency layer, because `NSImage.draw` resets the context alpha; glyphs in the glance and level fades now fade with their art. The backdrop panel lives in `Service/IslandBackdrop.swift`. The click on the expanded pill opens the pill menu once it has settled, never the launcher.

`Tests/nc-Island-expansion-test.swift` checks once per occurrence, a new occurrence, waiting behind a level, spending on a cut or a covered start, the window closing while waiting, and pruning (model proof). The DEBUG scenes `meeting-expand`, `meeting-expand-level` and `meeting-expand-palette` (`Service/IslandMeetingScenes.swift`) check the expansion, its settle to the exact glance size with no replay 5 s later, the wait behind a level and the cut, and the palette spend live on the test display (rendering proof). They drive the glance through `IslandCalendarGlance.preview(expands: true)` and shorten the expansion to 0.8 to 3 s, so each run ends inside the nine-second watchdog; the other glance scenes preview with `expands: false` and never expand.

The DEBUG scenes in `Service/IslandProfileScenes.swift` cover three profiles live. `notch-profile` and `notch-profile-glance` set `IslandController.simulatedNotch` (185 × 32 pt) before the island starts; two scenes keep each under the nine-second watchdog. `notch-profile` checks that a text notice opens below and around the notch under its `notice.<id>` key, that titled progress moves to the wings after one dwell, and that untitled progress keeps the notch covered and sits in wings beside it at the glance's width; `notch-profile-glance` checks the same for a status row, the expansion and the glance. Each state waits until the spring lands within 0.1 pt of that width before the check, because the headline and the expansion collapse into it. `reduce-motion` sets `IslandController.motion`, the engine's `ReducedMotionSetting`: under `.never` the level's spring overshoots its width, under `.always` the level and the expansion land with no overshoot. The DEBUG scene `headline-cap` (`Service/IslandOpeningScenes.swift`) posts a 200-character notice under the simulated notch and requires the headline to be the cap wide with a tail ellipsis, then a short one at its natural width. `status-overflow` shows six statuses on the notchless pill and three in the notch profile; the oldest drop, a tap acts on the newest, and with the newest cleared it acts on the next newest.

Not verified: the real `CalendarCoordinator` join-window transition, the island on a real notched screen (only the simulated notch is), VoiceOver speaking the announcement or value (only the in-process AX read is), the resting pill moving between two connected displays (only the presenter hand-over is), the system Reduce Motion switch (only the forced `.always` is) and sleep/wake.

## Update

`IslandUpdateActivity` (`Service/`), owned and started by `IslandCoordinator`, observes `UpdateCoordinator.stage` and mirrors only the update the user started; an automatic offer (`.available`), `.idle` and `.checking` show nothing. `IslandLiveState` (`Model/`) maps the stage to notice and status, all with id `update`: `.installing` holds one progress notice (`arrow.down.circle`, the installer phase's own "Downloading…" at received over expected, "Expanding…" and "Verifying…" with no fraction, so the pill shows the glyph alone rather than a full ring; untitled, so it stays compact on a notch) until the stage leaves installing; `.readyToRelaunch` posts "Update ready" with a 2.4 s dwell and sets the `arrow.clockwise.circle` status, both tapping through to the launcher where the palette's own pill offers Relaunch; `.failed` posts a failure notice "Update failed" with a 4 s dwell, which the presenter's queue runs out and sets the `exclamationmark.arrow.circlepath` status, both tapping `UpdateCoordinator.showFailure` (Try Again); a cancel back to `.available` ends the notice and clears the status. The status is set with the notice, which outranks it, so it shows once the notice ends. All strings are existing catalog ones. `Tests/nc-Island-live-test.swift` checks every stage and that cancel clears both (model proof). The DEBUG scene `update` (`Service/IslandUpdateScenes.swift`) injects stages through `IslandUpdateActivity.preview`, never a download, reads the value through in-process AX at each step, and checks the real 2.4 s ready dwell, that a tap on the ready status opens the palette, that the value is empty under the palette and returns on close without a new announcement, the failed notice then status (dwell shortened to 0.6 s to fit the watchdog), that cancel clears, and that the install announces "Downloading…" as it starts while "Expanding…" stays silent, then ready and failed once each. Its stills `update-download` (ring at 30 %, with "Downloading…" beside it only without a notch), `update-ready` (the ready status glyph) and `update-failed` (the failure notice) show what the pill draws; before the ready tap the scene waits for the pill's spring from notice to status to settle, since a moving pill takes no click. For the failure it sets the real stage through the DEBUG `UpdateCoordinator.previewFailure`, since `showFailure` guards on it, and checks that a tap on the failed status raises the "Update failed" question with Try Again as the default (read through the DEBUG `DialogController.shown`) and that Esc answers OK (the DEBUG `DialogController.lastAnswer` is the cancel index) and closes it with the failure kept; the still `update-try-again` shows that question.

The launch after an install reports on the island, not the stock HUD: `IslandUpdateActivity.report` takes `UpdateCheckStore.takeInstallReport()` from `AppCore` and posts `IslandLiveState(report:)`, a notice with id `update` and no status. The new version running posts "Updated to <version>" (`checkmark.circle`, the fork table's one new string) for the stock HUD's 2.4 s, tapping through to the launcher. A newer recorded install than the running version posts the failure notice "Update failed" for 4 s; its tap asks the stock question with the stock text ("<app> <version> could not be installed. Check for updates to try again.") and a Try Again button, which runs `UpdateCoordinator.checkForUpdates`, the stock check that offers the release in the launcher's pill. `Tests/nc-Island-live-test.swift` checks both notices (model proof). The DEBUG scene `install-report` (`Service/IslandInstallReportScenes.swift`) posts both reports with shortened dwells, checks the installed notice and its dwell, taps the failure notice, requires the "Update failed" question with Try Again as the default (through `DialogController.shown`) and the launcher closed, and answers Esc, which must answer OK and close it with no check started; the stills `install-report-installed`, `install-report-failed` and `install-report-try-again` show each. Not verified: a real relaunch after an install.
